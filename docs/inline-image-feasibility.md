# 行内图片角标可行性分析

> 背景:真书测试(《果然我的青春恋爱喜剧搞错了。 1》,Calibre 制作 EPUB2)暴露三期脚注的兼容缺口——
> 该书 23 组脚注全部是**图片型角标**(`<a epub:type="noteref"><sup><img src="note.png"/></sup></a>`),
> 现实现要求角标有文本才生成锚点,图片内容 `text()` 为空 → 角标静默丢失,脚注不可点。
> 本文分析"显示图片角标"(行内小图)的技术可行性,与"合成文本角标"方案对比。
> 状态基线:2026-10(v1.2.0)。

## 一、原书角标的样子

`OEBPS/Images/note.png`:20×20 像素 RGBA,红色圆形图标、白色"注"字(见 `shots/note_marker_4x.png`)。
原书正文效果:脚注位置内嵌该行内小图,底边贴基线。

## 二、可行性结论

**可行,无结构性障碍**。核心依据:块级图片段(二期)已经用 U+FFFC 占位符把图片锚定在投影上,
行内小图复用同一模式——占位符机制、偏移轴、进度/选区全部零改动,差异只在渲染形态(行内 vs 独占行)。
问题是改动面:约 200 行核心改动 + 测试,横跨解析/断行/物化/绘制四层。

## 三、技术方案

### 核心思路

行内图片 = 投影占位字符 U+FFFC + 行内渲染。段落记 `inlineImages: [(charIdx, 图片路径)]`,
排版断行用 ReplacementSpan 提供真实尺寸度量,绘制层在占位符位置画 Bitmap。

### 五处改动

| 层 | 改动 | 规模 |
|---|---|---|
| 解析侧 | noteref `<a>` 无文本时扫子节点 `<img>` → 投影落 U+FFFC,段落记 inlineImages;章文件加字段(格式 v4→v5,老书自动升级机制现成) | ~20 行 |
| 断行度量 | compose 时给占位符挂 **ReplacementSpan**,`getSize()` 返回图片等比尺寸(断行时按需读图片头)。StaticLayout 原生支持;`getSize` 为确定性函数,与 `BREAK_STRATEGY_SIMPLE` 确定性断行要求兼容 | ~25 行 |
| 物化 | 行文本扫描 U+FFFC → 折算段落 inlineImages → `DrawLine` 增加行内图片标记(字符位置+尺寸) | ~20 行 |
| 绘制 | drawText 按占位符切段(与现有样式段绘制同一模式,否则字体画豆腐块),图片在占位符位置 drawBitmap、底边贴基线;与两端对齐正交(U+FFFC ≥ 0x2E80 被 tokenize 当宽字符独立成词元,拉伸自然工作) | ~40 行 |
| 防呆 | 行内图片高 > 约 1.5×字号时降级为块级(防大图撑爆行高);小图标才走行内 | ~10 行 |

### 已验证的支撑点

- U+FFFC 占位模式:二期图片段(独占行)已在线上验证,偏移/进度/选区机制零改动
- ReplacementSpan × BREAK_STRATEGY_SIMPLE:span 尺寸函数确定性,不破坏持久化分页缓存的一致性前提
- justify 正交:tokenize 的宽字符判定区间(≥0x2E80)天然覆盖 U+FFFC(0xFFFC)

## 四、风险点(可控的正交细节)

1. **justify/样式段/选区几何**每处都要正确处理 U+FFFC:分段绘制已有先例(样式段),选区选中占位符
   会复制出 U+FFFC 字符(轻微瑕疵,系统阅读器同样存在);
2. 断行度量的性能:ReplacementSpan.getSize 按需读图片头,已有限流路径(章断行缓存),图标 20×20 读取成本可忽略;
3. 章文件再次升版(v4→v5):已有自动升级链路(upgrade_tmp 安全替换 + migrateProgress 进度迁移),
   老书打开即升级,无人工干预。

## 五、与合成文本角标对比

| | 合成"注"字角标 | 行内图片(本方案) |
|---|---|---|
| 改动量 | ~10 行 | ~200 行 |
| 观感 | "注"字上标,颜色跟阅读主题 | 原书红底白"注"图标,100% 还原 |
| 能力范围 | 仅脚注角标 | 通用行内小图能力(此后任意 EPUB 行内小图可显示) |
| 风险 | 几乎无 | 中等(正交细节多) |
| 依赖 | 无 | 无新依赖(复用 androidsvg/Bitmap 管线) |

注:原书图标即白字"注",合成方案的信息内容与原书一致,仅缺红底圆形外形。

## 七、结论

- 行内图片**技术上可行**,主要成本在绘制层与占位符的正交细节,无架构性障碍;
- 决策点:观感还原 + 通用能力(行内图片,~200 行) vs 最小改动(合成"注"字,~10 行);
- 两者不互斥:可先落合成角标(立刻修复真书脚注不可点),行内图片作为独立增强后续排期;
- 无论哪种,已有书均通过打开时自动升级获得角标,进度不漂移;
- 回归用例已备:`sample_测试书_v5.epub`(图片型角标场景)。
